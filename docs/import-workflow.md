# 导入游戏的安全流程

本工具只负责**制作**三层呼吸图 BMP；写进游戏资源包由导入工具完成。
以下是实践中踩过坑之后沉淀的流程，按它走可以把"改坏整个资源包"的
风险降到最低。

## 1. 确定目标槽位

1. 从实际新武将数据、游戏界面或经验证的配置建立"目标人物 → 可写资源
   槽位"映射，核对槽位是否被其他人物占用。人物档里的头像字段不一定
   等于 S13 包的资源槽位；用现有资源解码结果交叉确认，不要按名单顺序猜。
2. 读取当前安装的索引、包内子表和目标资源，核对容量、纹理尺寸、层数
   及压缩格式（见 [s13-package-format.md](s13-package-format.md)）。
3. 为每个目标记录：人物、槽位、原图、各输出资源、预期 UI 位置；给原图
   及候选文件计算哈希。

## 2. 暂存、导入与回读

1. 导入前确认游戏进程已退出；记录待写包和相关人物档的哈希，制作整包
   备份。比较新旧压缩载荷长度；容量不足时调整素材或编码，不侵占下一
   资源或无关区段。
2. **先写独立暂存包**（不动 Live 包）。逐项解码回读，核对人物与槽位、
   纹理尺寸、层数、格式和内容；与原包比较，确认只有目标载荷及必要的
   长度字段发生变化。
3. 激活前再次核对 Live 包哈希与备份，并确认游戏仍已退出。激活后从
   Live 包重新读取目标资源，记录最终哈希、回退文件和结果。任何检查
   失败就停止激活或回滚——暂存成功不等于已导入。

## 3. 游戏内验收

分别检查新武将列表、详情页和呼吸动画。如果文件回读已通过但列表仍
显示旧头像，定向检查列表图集，不要盲扫全部资源包。

建议按阶段记录结论，且不把一种证据当成另一种：

| 阶段 | 含义 |
| --- | --- |
| PREPARED | 素材已生成、预览通过 |
| STAGED_VERIFIED | 暂存包回读通过 |
| LIVE_IMPORTED_READBACK_PASS | Live 包导入且回读通过 |
| SCREENSHOT_PASS / USER_OBSERVED_PASS | 截图 / 本人实机观察确认 |
| GAME_RUNTIME_PASS | 完整游戏运行验收 |

## 常见坑

- 槽位被别的武将占用 → 别人的头像被顶掉；
- 压缩载荷变长 → 挤占下一个资源，出现串图或崩溃；
- 只改了呼吸图没改列表图集 → 列表里还是旧头像；
- 游戏没退出就写包 → 写入被占用文件，包损坏。
